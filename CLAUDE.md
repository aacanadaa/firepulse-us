## Commands

pnpm monorepo (Node 20+). Workspaces: `apps/api` (`@firepulse/api`), `apps/web` (`@firepulse/web`), `packages/protocol` (`@firepulse/protocol`).

```bash
pnpm install
pnpm dev                 # API (:8790) + web (:3000); uses `&`, so on Windows run dev:api and dev:web in separate shells
pnpm dev:api             # tsx watch, API only
pnpm dev:web             # next dev, web only
pnpm typecheck           # all workspaces
pnpm test                # vitest, API only
pnpm build               # protocol → api → web
pnpm basemap:build       # regenerate apps/web/public/basemap/firepulse.pmtiles from Natural Earth
```

Single test file / test name:

```bash
pnpm --filter @firepulse/api exec vitest run test/fusion.test.ts
pnpm --filter @firepulse/api exec vitest run -t "merge"
```

There is no linter configured (Next build ignores ESLint).

**`@firepulse/protocol` resolves to its compiled `dist/`.** The API and web `predev`/`prebuild` hooks rebuild it, but `pnpm test` and `pnpm typecheck` do not. After editing anything in `packages/protocol/src`, run `pnpm --filter @firepulse/protocol build` before running API tests or typechecking, or you will be testing stale code.

No database or keys are needed: without `DATABASE_URL` the API uses `MemoryStore`, and `DATA_MODE` defaults to `simulation`. See `.env.example` for all tuning variables (`FUSION_*`, snapshot budgets, `FIRMS_MAP_KEY`, `INGEST_WEBHOOK_SECRET`). Full PostGIS + Redis stack: `docker compose up --build`; migrations/seed via `pnpm db:migrate` / `pnpm db:seed` (need `DATABASE_URL`).

`scripts/shot.mjs` (headless screenshot + console/WebGL diagnostics) hardcodes `/usr/bin/chromium-browser`, so it needs adjusting to run on Windows.

## Architecture

Deep dive lives in `docs/ARCHITECTURE.md`. The big picture:

**Data flow.** Source adapters → `Pipeline` (`apps/api/src/pipeline.ts`) → `Store` → `FusionEngine` (`fusion/engine.ts`, runs every `FUSION_INTERVAL_MS`) → `RealtimeHub` (`realtime/hub.ts`) → WebSocket → client store (`apps/web/src/lib/store.ts`) → MapLibre + deck.gl (`components/MapCanvas.tsx`, `lib/layers.ts`). Wiring happens in `apps/api/src/index.ts`.

**Adapters only fetch and normalise.** `SourceAdapter.poll()` returns `RawSignal[]` and never touches the engine or hub. Official perimeters use a sibling `OfficialAdapter` because they produce incidents, not point evidence. The simulator (`sources/simulated.ts` + `simulation/generator.ts`) is a contract-compatible adapter, not a mock: `DATA_MODE=simulation|live|hybrid` swaps adapters only, and fusion/transport/client code is identical in every mode. Tier-1 webhooks (`/api/v1/hooks/cad`, `/hooks/crowd` in `server.ts`) ingest directly and re-run fusion right away.

**Normalisation invariants (pipeline).** `observedAt` and `receivedAt` are kept separate; every signal gets an H3 res-8 cell and a `dedupeKey` (dedupe enforced by both stores); range-bearing observations (PTZ cameras, crowd bearings) are projected to the target location before fusion.

**Store port.** `store/types.ts` defines `Store`; `MemoryStore` and `PostgresStore` must keep identical semantics. If `DATABASE_URL` is unreachable the API falls back to memory. Schema changes touch `db/migrations/001_init.sql`, `store/postgres.ts`, and `store/memory.ts` together. `RedisCache` is best-effort (GEO bbox cache + Pub/Sub fan-out of deltas across pods); a Redis outage must degrade, never error.

**One incident model.** Estimates and official fires share one `IncidentFeature` type / `fire_incident` table, with a `kind: 'estimated' | 'official'` discriminator. Merging an estimate into an official perimeter sets `merged_into`, attaches a `precursor` (lead time) to the official incident, unions sources, and writes the merge ledger. Official revisions must keep `precursor`. Estimates are clamped to 99 confidence; only official data reaches 100.

**Shared protocol package.** `packages/protocol` is the single source of truth for domain types, the realtime message contract (`ServerMessage` etc.), the noisy-OR confidence model (`confidence.ts`), and dependency-free geodesy plus DBSCAN (`geo.ts`). Both API and web import it. Calibration targets in `apps/api/test/confidence.test.ts` (e.g. lone crowd ≈20%, CAD+GOES ≈85%) are the contract for any confidence change.

**Realtime transport is delta-based.** First frame is a `snapshot`, then `delta` frames with `incidentsUpsert/Remove` and `hotspotsUpsert`. The engine only sends incidents whose signature changed, and estimate IDs stay stable across ticks so the client patches rather than re-adds. Hotspots go through a sequenced ring buffer (`realtime/hotspots.ts`); clients only receive `seq > lastHotspotSeq` within their bbox, and pans only trigger a new snapshot when the viewport leaves the covered area. `stats` frames (1 Hz) carry no geometry. The client keeps `Map<id, feature>` and never re-fetches the full dataset.

**Frontend rendering split.** MapLibre owns basemaps (self-hosted PMTiles for Atlas/Ink; Esri/EOX rasters for Topo/Satellite) and the hatched official perimeters; deck.gl (`MapboxOverlay`, non-interleaved) owns estimates, hotspots, H3 cells, and labels; wind particles run on a separate Canvas 2D (`WindParticles.tsx`). Basemap switches call `map.setStyle` and must re-install the official source/layers (see `lib/places.ts`, `MapCanvas.tsx`). The web app reads `NEXT_PUBLIC_API_URL`, or falls back to the page host on port 8790.

**Design system constraints** (README "Design system"): alabaster canvas, 1px hairlines, Inter + JetBrains Mono, and exactly two data accents: Forest `#1B4332` for official data and International Orange `#FF4F00` for estimates. No shadows, gradients, glows, pills, or hover scale. 6px radii, 150ms ease-out. Wind stays monochrome. UI tokens are CSS variables in `apps/web/src/app/globals.css` (Tailwind v4). Map colours are set per basemap theme in `lib/places.ts`.
